# ADR 0015: Typed tool schemas

## Status
Accepted.

## Context
Constitution rule 6 requires an ADR to grow the public API. Typed routes (`post(path, In.class, (p, in) -> ..)`) already know the record they bind, but MCP `tools/list` advertised every body as `{"type":"object"}` and OpenAPI had no `requestBody`. Agents had to guess field names and types, which costs a failed call per guess. One record should drive binding, validation, the MCP input schema and the OpenAPI request body.

## Decision
- `Route` gains a fourth component, `Class<?> input`: the body type of a typed POST, PUT or PATCH, else `null`. The three-argument constructor stays, so existing code and tests compile. Mounting a router and tagging with `.tool(..)` keep the input.
- `Route.inputSchema()` returns the JSON Schema (2020-12) of `input`, or `null`. It is generated by `in.jolt.internal.json.Schema`, which follows what the built-in binder accepts: records become `object` with `properties` and `required` (every component except `Optional`), strings, integers, numbers (including `BigDecimal`), booleans, enums (`enum` of constant names), `UUID` and `java.time` types (`string` with `format`), collections and arrays (`array` with `items`), and `Map<String, V>` (`additionalProperties`). Unsupported types and recursive references become `{}`, so the output stays small and has no `$defs`.
- `additionalProperties: false` is not emitted, because the binder ignores unknown fields; the schema describes what the server accepts.
- `jolt-mcp`: a typed tool's `body` property is the record schema and `body` becomes required. A successful call whose reply is a JSON object also returns it as `structuredContent` (MCP 2025-06-18), next to the text content.
- OpenAPI: typed operations get a required `application/json` `requestBody` with the schema.
- `GET /_jolt/routes` writes `input` as the record's simple name, since a `Class` is not JSON.

## Consequences
- Agents see real field names, types and required fields, and OpenAPI clients can generate request types.
- No output schema: `Typed.Read<O>` loses `O` to erasure at runtime, so the reply type is unknown. A later ADR can add an explicit output class if needed.
- Schemas carry types only. Constraints checked in code with `Rules` (ranges, patterns) are not reflected.
- Public API growth: one record component, one constructor, one method. `llms.txt` grows by one sentence.
